# Scanning contract

This is the agreement between the Affilova app and the scanner service in
`services/scanner`. It covers `POST /scan`, `POST /selftest` and `GET /healthz`. Both sides must be changed together: the request shape, the
response codes and the callback signature below are what the app validates.

## Request

```
POST {SCANNER_URL}/scan
Authorization: Bearer <SCANNER_SHARED_SECRET>
Content-Type: application/json
```

```json
{
  "scanId": "6af469de-05d7-4ae1-9d69-b68600000001",
  "fileId": "6af469de-05d7-4ae1-9d69-b68600000002",
  "downloadUrl": "https://<bucket>.r2.cloudflarestorage.com/vendor/file.pdf?X-Amz-Signature=...",
  "expectedSizeBytes": 1234,
  "extension": "pdf",
  "callbackUrl": "https://app.affilova.com/api/internal/scan-result"
}
```

| Field | Rule |
| --- | --- |
| `scanId` | uuid, generated by the app, echoed back on the callback |
| `fileId` | uuid of the vendor file record |
| `downloadUrl` | https, no credentials, no non-default port, host must end with `ALLOWED_DOWNLOAD_HOST_SUFFIX` and must not be an IP literal |
| `expectedSizeBytes` | integer, the exact byte size of the object |
| `extension` | lowercase, no dot, one of the accepted types below |
| `callbackUrl` | https, origin in `ALLOWED_CALLBACK_ORIGINS`, path exactly `/api/internal/scan-result` |

Accepted extensions: `pdf`, `epub`, `mobi`, `zip`, `7z`, `rar`, `mp4`, `mov`,
`mp3`, `wav`, `m4a`, `docx`, `xlsx`, `pptx`, `txt`, `csv`, `png`, `jpg`, `jpeg`,
`psd`, `ai`, `eps`, `ttf`, `otf`.

Request bodies over 8 KB are rejected.

## Responses

| Status | Body | Meaning |
| --- | --- | --- |
| 202 | `{"accepted":true}` | queued; the result arrives on the callback |
| 400 | `{"error":"invalid_request","field":"..."}` | a field failed validation |
| 400 | `{"error":"invalid_json"}` | the body is not JSON |
| 401 | `{"error":"unauthorized"}` | missing or wrong secret; no detail is ever returned |
| 413 | `{"error":"payload_too_large"}` | body over 8 KB |
| 429 | `{"error":"queue_full"}` + `Retry-After` | queue is full, try again later |
| 503 | `{"error":"not_ready"}` | clamd is not answering or the signatures are older than 72 hours |
| 503 | `{"error":"shutting_down"}` | the service is stopping |

`GET /healthz` answers `200` with `{"ok":true,"clamd":true,"signatureAgeHours":N}`
only when clamd answers `PING` and the signature database is younger than 72
hours. Otherwise it answers `503` with the same shape and `ok:false`
(`signatureAgeHours` is `null` when there is no database). Every other path
answers `404`.

## Self-test

```
POST {SCANNER_URL}/selftest
Authorization: Bearer <SCANNER_SHARED_SECRET>
Content-Type: application/json
```

```json
{
  "downloadUrl": "https://<bucket>.r2.cloudflarestorage.com/selftest/<uuid>/hello.txt",
  "expectedSizeBytes": 26,
  "extension": "txt"
}
```

The self-test exists so an operator can prove the whole chain (storage, the
service, ClamAV and the policies) without creating a product or a file record. It
runs the **same pipeline** as `POST /scan` — download with the size cap, libmagic
type detection, the MIME policy, the archive policy, ClamAV and the temporary
file cleanup — and answers with the verdict instead of queueing and calling back.
It is one function in the service (`runScanPipeline`), so a passing self-test
cannot come from a second implementation that a real scan never runs.

| Field | Rule |
| --- | --- |
| `downloadUrl` | exactly the same guard as a scan: https, no credentials, no non-default port, host must end with `ALLOWED_DOWNLOAD_HOST_SUFFIX`, no IP literal |
| `expectedSizeBytes` | integer from 1 to 2097152 (2 MiB); a self-test is small on purpose |
| `extension` | the same accepted list as a scan |

There is no `scanId`, no `fileId` and no `callbackUrl`: nothing is recorded, so
there is nothing to echo.

| Status | Body | Meaning |
| --- | --- | --- |
| 200 | `{"verdict":…,"detail":…,"sha256":…,"detectedMime":…,"engine":…,"signatureVersion":…,"durationMs":N}` | the pipeline ran; the verdict is the answer |
| 400 | `{"error":"invalid_request","field":"…"}` | a field failed validation |
| 400 | `{"error":"invalid_json"}` | the body is not JSON |
| 401 | `{"error":"unauthorized"}` | missing or wrong secret, checked before the body is read |
| 413 | `{"error":"payload_too_large"}` | body over 8 KB |
| 429 | `{"error":"selftest_busy"}` + `Retry-After` | another self-test is already running |

A verdict of `infected`, `rejected`, `needs_review` or `error` is a **200**: the
caller asked what the chain does, and a failure is an answer. The overall budget
is 25 seconds; a self-test that overruns answers `200` with `verdict: "error"` and
`detail: "timeout"`. Only one self-test runs at a time, so two operators cannot
load the service through this route.

The self-test does **not** exercise the callback route or the database. Those are
covered by uploading a real file in a product; `docs/scanning.md` says the same
where staff read it.

## Callback

```
POST {callbackUrl}
Content-Type: application/json
X-Scanner-Timestamp: <unix seconds>
X-Scanner-Signature: <hex HMAC-SHA256 of `${timestamp}.${rawBody}`>
```

```json
{
  "scanId": "6af469de-05d7-4ae1-9d69-b68600000001",
  "fileId": "6af469de-05d7-4ae1-9d69-b68600000002",
  "verdict": "clean",
  "detail": "clean",
  "sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08",
  "detectedMime": "application/pdf",
  "engine": "clamav",
  "signatureVersion": "28186",
  "scannedAt": "2026-11-18T05:00:00.000Z"
}
```

* `verdict` is one of `clean`, `infected`, `rejected`, `needs_review`, `error`.
* `detail` is at most 300 characters and never contains a URL.
* `sha256` is the hex SHA-256 of the downloaded bytes, or `null` when the
  download never completed.
* `detectedMime` is what libmagic reported, or `null`.
* `engine` is always `"clamav"`.
* `signatureVersion` is the ClamAV database version, or `null`.
* `scannedAt` is an ISO 8601 timestamp.

The app must answer `200 {"ok":true}`, including for a duplicate callback. On any
non-2xx answer or network error the service retries after 10 s, 30 s, 2 min,
10 min, 30 min and 2 h, then gives up (seven attempts in total); the app's
sweeper picks up anything the callback never delivered.

The signature is computed over the exact bytes of the body as sent, so the app
must verify against the raw request body before parsing it. A stale
`X-Scanner-Timestamp` should be refused by the app.

### Test vector

Both sides use this vector in their tests, so a change to the signing on either
side fails a test instead of silently producing 401s in production.

* secret: `0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef`
* timestamp: `1763000000`
* body (exactly this byte sequence):

```
{"scanId":"6af469de-05d7-4ae1-9d69-b68600000001","fileId":"6af469de-05d7-4ae1-9d69-b68600000002","verdict":"clean","detail":"clean","sha256":"9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08","detectedMime":"application/pdf","engine":"clamav","signatureVersion":"28186","scannedAt":"2026-11-18T05:00:00.000Z"}
```

  `731104f6dda6976ce558fc83e2a1238b50b89b06e2c36972671208d2f89a5ef2`

## Verdicts and detail codes

The service applies the checks in this order and stops at the first one that
decides:

1. `size_mismatch` — the download did not match `expectedSizeBytes`
2. type policy — what libmagic found does not match the extension
3. archive policy — what `7z l -slt` lists inside the archive
4. ClamAV
5. `clean`

| Verdict | Detail | Cause |
| --- | --- | --- |
| `infected` | the signature name, e.g. `Eicar-Test-Signature` | ClamAV found malware |
| `rejected` | `type_mismatch` | detected type is outside the set for that extension |
| `rejected` | `executable_type` | detected type is executable, script or active content, for any extension |
| `rejected` | `encrypted_archive` | an entry is encrypted, or ClamAV raised `Heuristics.Encrypted.*` |
| `rejected` | `archive_limits` | entry count, total size, compression ratio or nesting depth over the limit, or ClamAV raised `Heuristics.ExceedsMax*` |
| `rejected` | `path_traversal` | an entry escapes the extraction root (`../`, leading `/`, drive letter) |
| `rejected` | `symlink` | an entry is a symbolic link |
| `rejected` | `size_mismatch` | bytes on disk are not `expectedSizeBytes` |
| `needs_review` | `archive_contains_executable` | an entry name ends in `exe`, `msi`, `bat`, `cmd`, `com`, `scr`, `vbs`, `ps1`, `jar`, `apk`, `dll`, `sh`, `app`, `dmg`, `js`, `so` or `pkg` |
| `needs_review` | `archive_unlistable` | 7-Zip could not list the archive, for example a RAR5 file |
| `error` | `download_failed` | the object could not be fetched |
| `error` | `scanner_error` | ClamAV, 7-Zip or libmagic failed |
| `error` | `timeout` | the job exceeded its 20 minute budget or a stage timed out |

Only `clean` may be treated as "safe to publish". `needs_review` must go to a
human, and everything else must block the file.

## Archive limits

* at most 10 000 entries
* at most 8 GiB uncompressed in total
* at most a 1000:1 overall compression ratio
* at most three levels of archive nesting
